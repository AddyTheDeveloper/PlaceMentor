    1. Basics of DBMS (Theory & Interview)

    DBMS vs File System: A DBMS is software used to manage data efficiently. Unlike File Systems, it provides Data Independence, Security, and Concurrent Access.

    Why DBMS over File System?

    No Redundancy

    Minimizes data duplication via normalization.

    Data Security

    Access control levels for different users.

    Concurrent Access

    Multiple users can read/write simultaneously.

    Interview Focus: Data Models
    • Relational: Data in tables (Rows/Cols). Most popular.
    • NoSQL: Schema-less data (JSON/BSON). Used for Big Data.
    • Hierarchical: Tree-like structure (Parent-Child).

    3. Relational Model & Database Keys

    Keys are attributes used to uniquely identify tuples (rows) in a relation.

    Key TypeDescription
    Super KeyAny set of attributes that uniquely identifies a row.
    Candidate KeyMinimal Super Key. No redundant attributes.
    Primary KeyChosen candidate key. CANNOT be NULL.
    Foreign KeyReference to Primary Key of another table.

    Interview Gold: Can a table have multiple Primary Keys?
    Answer: No, only one. But it can have multiple Candidate Keys and one Composite Key (PK made of 2+ cols).

    4. Functional Dependency (The Core)

    Functional Dependency (X → Y): If two tuples have same values for X, they MUST have same values for Y.

    Types of FDs

    • Trivial: X → Y where Y ⊆ X (e.g., {ID, Name} → {ID}).
    • Non-Trivial: X → Y where Y is not a subset of X (e.g., ID → Name).
    Attribute Closure (X+)

    The set of all attributes that can be functionally determined from X.

    Example: F = {A → B, B → C, C → D}. Find A+.

    Step 1: A+ = {A}
    Step 2: A → B, so A+ = {A, B}
    Step 3: B → C, so A+ = {A, B, C}
    Step 4: C → D, so A+ = {A, B, C, D}

    5. Normalization (Data Hygiene)

    Process of organizing data to reduce redundancy and improve data integrity.

    1NF (First Normal Form)

    Attributes must be Atomic (No multi-valued attributes like multiple phone numbers in one cell).

    2NF (Second Normal Form)

    In 1NF + No Partial Dependency. (Every non-prime attribute must depend on the WHOLE candidate key, not just a part of it).

    3NF (Third Normal Form)

    In 2NF + No Transitive Dependency. (Non-prime attributes shouldn't depend on other non-prime attributes).

    BCNF (Boyce-Codd NF)

    Technically stronger than 3NF. For every FD X → Y, X must be a Super Key.

    Placement Trick: If a table has a single-attribute candidate key, it is automatically in 2NF.

    ACID Breakdown:
    1. Atomicity: All or nothing.
    2. Consistency: DB remains in valid state.
    3. Isolation: Transactions don't interfere.
    4. Durability: Changes are permanent.

    Isolation Levels
    1. Read Uncommitted: Allows Dirty Reads.
    2. Read Committed: No Dirty Reads.
    3. Repeatable Read: No Non-repeatable Reads.
    4. Serializable: Highest level, strict.

    8. Locks & Deadlock Prevention

    Concurrency Problems

    ProblemDescription
    Dirty ReadReading data that hasn't been committed yet.
    Lost UpdateTwo transactions update same row; one is lost.
    Phantom ReadReading a set of rows that changes due to another transaction.

    Shared Lock (S): Used for Reading. Multiple S-locks allowed.
    Exclusive Lock (X): Used for Writing. Only one X-lock allowed.

    Deadlock Prevention
    • Wait-Die: Older waits for younger, younger dies.
    • Wound-Wait: Older wounds younger, younger waits.

    9. Indexing & B+ Trees

    Indexing: Data structure technique to quickly retrieve records. It reduces the number of disk accesses required for queries.

    FeatureClustered IndexNon-Clustered Index
    Data StorageDirectly on leaf nodes.Separate structure with pointers.
    NumberOnly ONE per table.Multiple allowed.
    SpeedFaster for range searches.Slower (requires extra jump).
    B-Trees vs B+ Trees

    DBMS uses B+ Trees because data is stored only in leaf nodes, which are linked together for faster range queries.

    DBMS Placement FAQ

    Q1: What is the difference between Primary Key and Unique Key?
    Primary Key cannot be NULL and there's only one per table. Unique Key can have one NULL and there can be multiple.
    Q2: Explain the difference between DELETE, TRUNCATE, and DROP.
    DELETE (DML) removes rows with rollback. TRUNCATE (DDL) removes all rows without rollback. DROP (DDL) removes table structure.
    Q3: What is a View?
    A virtual table based on the result-set of an SQL statement.
    Q4: Why B+ Trees are preferred over B-Trees for indexing?
    B+ Trees store data only in leaf nodes, which allows more keys in internal nodes (lower height) and linked leaf nodes enable faster range queries.
