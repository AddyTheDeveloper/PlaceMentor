    1. Asymptotic Analysis (The Math of Code)

    Master Theorem: T(n) = aT(n/b) + f(n)

    • Case 1: If f(n) < nlogba, then T(n) = Θ(nlogba).
    • Case 2: If f(n) = nlogba, then T(n) = Θ(nlogba * log n).
    • Case 3: If f(n) > nlogba, then T(n) = Θ(f(n)).
    NotationMeaningRate of Growth Description
    O(1)ConstantFastest. Independent of input size.
    O(log n)LogarithmicHighly efficient (e.g., Binary Search).

    O(n log n)Log-linearEfficient comparison sorts (e.g., Merge Sort).

    3. Advanced Paradigms: DP vs Greedy

    Dynamic Programming (DP)

    Solves sub-problems once and stores their solutions to avoid redundant calculations. Requires overlapping sub-problems and optimal substructure.

    • Memoization: Top-down approach (Recursion + Cache).
    • Tabulation: Bottom-up approach (Iteration table).
    • Examples: Longest Common Subsequence (LCS), 0/1 Knapsack, Matrix Chain Multiplication.

    Greedy Strategy

    Makes the local optimal choice at each stage in hopes of finding the global optimum. Fast but doesn't guarantee global optimality for all problems.

    • Does not backtrack or re-evaluate past decisions.
    • Examples: Huffman Coding, Fractional Knapsack, Dijkstra's Shortest Path, Prim's/Kruskal's MST.
    Placement Case Study: 0/1 Knapsack vs Fractional Knapsack

    0/1 Knapsack: Items cannot be split. Greedy fails because taking the highest value-to-weight ratio item might leave unused capacity that could be filled better. Must use **DP**.

    Fractional Knapsack: Items can be divided. **Greedy** works optimally by sorting items by value/weight ratio and taking as much as possible.

    Longest Common Subsequence (LCS) Trace

    Matches character sequences between strings (e.g., "ABCDE" and "ACE").

    • If characters match: LCS[i][j] = 1 + LCS[i-1][j-1]
    • If mismatch: LCS[i][j] = Max(LCS[i-1][j], LCS[i][j-1])

    Complexity: O(m*n) time and space using a 2D DP matrix.

    Dijkstra's Algorithm Trace

    Finds the shortest path from a single source vertex to all other vertices in a weighted graph with non-negative edge weights.

    1. Initialize distances: Dist[Source] = 0, Dist[others] = ∞. Push source to Min-Heap PQ.
    2. Extract minimum distance node u from PQ.
    3. Relax all edges: For each neighbor v of u, if Dist[u] + weight(u,v) < Dist[v], then update Dist[v] = Dist[u] + weight(u,v) and push to PQ.
    4. Repeat until PQ is empty. Complexity: O((V+E) log V).

    4. Backtracking (Recursive Search)

    Backtracking: A refinement of brute-force search. It builds candidates recursively and abandons a candidate ("backtracks") as soon as it determines the candidate cannot possibly lead to a valid solution.

    Standard Problems: N-Queens (placing queens on chessboard without conflicts), Sudoku Solver, Rat in a Maze, Subset Sum.

    5. String Matching Algorithms

    Knuth-Morris-Pratt (KMP) Algorithm: String matching in O(n + m) time. Uses a prefix function (LPS array) to bypass redundant comparisons on mismatch, eliminating back-tracking on the text pointer.

    Rabin-Karp Algorithm: Uses a rolling hash function to search for pattern matches in O(n + m) average time. Sped up by modulo arithmetic to prevent integer overflow.

    6. Complexity Theory (P vs NP)

    P (Polynomial Time)

    Problems that can be solved by a deterministic Turing machine in polynomial time O(nk). (e.g., Searching, Sorting).

    NP (Nondeterministic Polynomial Time)

    Problems whose solutions can be verified in polynomial time. (e.g., Sudoku, Integer Factorization).

    NP-Hard

    Problems that are at least as hard as the hardest problems in NP. They do not have to be in NP themselves. (e.g., Halting Problem).

    NP-Complete

    The intersection of NP and NP-Hard. These are the hardest problems in NP. If one is solved in polynomial time, all can be solved. (e.g., Traveling Salesperson (TSP), 0/1 Knapsack).

    Placement FAQ: Algorithms

    1. When should I use DP vs Recursion/Memoization? Use DP when sub-problems overlap and you need optimal substructure. Bottom-up tabulation is often preferred over recursion due to call stack overhead.
    2. Compare QuickSort and MergeSort. MergeSort is stable and operates in guaranteed O(n log n) time but requires O(n) helper space. QuickSort is unstable, runs faster in-place with O(log n) stack, but degrades to O(n²) in the worst case (unless randomized pivot is used).
    3. What is the Master Theorem? A shortcut formula for solving recurrence relations of the form: T(n) = aT(n/b) + f(n).
    4. Explain Dijkstra's Algorithm limits. It cannot handle negative edge weights because it assumes greedily visited nodes are finalized, which is false if negative weights decrease path costs later (use Bellman-Ford instead).
